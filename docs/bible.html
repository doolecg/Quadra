1. What it is

Quadra is a free, open-source 3D app for modelling, animation and rendering that works like 3ds Max 2026. It has the same layout, the same shortcuts and the same ways of working, so a Max user can sit down and keep going. It is built from scratch in Rust and renders with Cycles, the engine inside Blender, without using Blender itself. It aims to start faster, handle bigger scenes and crash less than Max.

It is not a Max plugin, it does not open .max files, and it does not run Blender add-ons. Scenes move in and out through USD, FBX, OBJ and glTF. It is a long-term project: full Max parity is years of work, so the first target is milestones 1 to 3.

2. Pillars

Every feature must serve at least one.

  1. Max muscle memory. Panels, shortcuts and workflows are where a Max user expects them. Example: the 480 Max shortcuts work out of the box.
  2. Fast. Under 3 seconds to start, 10 million triangles at 60 FPS, a modifier stack that uses every CPU core. Example: changing a modifier on a 1M-polygon mesh updates in under 50 ms.
  3. Never lose work. Unlimited undo, autosave that never freezes the app, crash recovery. Example: kill the app mid-edit and lose at most 30 seconds.
  4. Open and portable. Open source, Windows first then Linux and macOS, USD as the native file, plugins that keep working after updates.

4. Milestone map and build tracker

Each milestone lists its scope, then the 3ds Max features it must match (open "Max features to match"). Placement: M1 50, M2 41, M3 13, M4 16, M5 9, unplaced v1 126, later 45. It follows the research's module and priority for each feature; review it at each milestone's start. A ticked item is built and checked in the running app. Items marked UNVERIFIED were not confirmed against a 2026 help page.

5. How a milestone runs

  1. Start: Claude writes docs/milestone-N-guide.html (goal, parts, out of scope) and asks doole every question it needs in one bundle.
  2. doole approves the guide. Claude marks it "In progress: approved" with the date here and in CLAUDE.md.
  3. Claude builds one small step, writes its test steps in the guide, and stops. doole checks it before the next step. Fixes jump the queue.
  4. End: a short review checklist in the guide covering the milestone's "done when" targets.
  5. Close: Claude marks it done here and in CLAUDE.md, ticks its scope and feature items in section 4, updates docs/systems.md, records decisions in section 3 and docs/design.md, and adds a line to section 8.

6. Where ideas go

  • Fits a planned milestone: add it to that milestone in section 7.
  • Needs something not built yet: park it under the milestone that builds that thing.
  • Serves no pillar: park it under "Maybe never" with one line on why.
  • Changes a settled decision: ask doole; it is not decided until doole says so.
  • Never slip it into the milestone in progress, however small.
