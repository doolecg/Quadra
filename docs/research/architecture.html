Quadra architecture and plan

Phase 4 of the Quadra research, written 2026-10-27. It builds on the 3ds Max 2026 teardown, the Blender engine study and the Rust stack study. Claims about outside software are sourced on those pages; this page links back to them instead of repeating them.

Read this first

  1. Route: a Rust app that links standalone Cycles (Apache-2.0) through a thin C++ wrapper. We do not link Blender or bpy. See section 1 and blender-engine.html.
  2. Licence: we may pick any licence for Quadra, closed or open, because nothing GPL is linked. Cycles' own dependencies are permissive, apart from a few marked UNVERIFIED there.
  3. Stack: egui with egui_dock for the UI, wgpu for the viewport, our own dependency graph with rayon for the modifier stack, persistent data for undo, PyO3 for scripting, USD as the native file format.
  4. The first job is a viewport prototype that proves 10M triangles at 60 FPS. No benchmark found online shows wgpu at 50M triangles, so this is the biggest unknown.
  5. Section 9 is the one-page summary: the chosen route, the licence, the top 10 Max pain points we fix, and the risks.
  6. 3ds Max 2027 has already shipped. We keep 2026 parity as the target and review 2027 changes before M2.

1. Architecture diagram

+---------------------------------------------------- Quadra process (Rust) ----------------------------------------------------+
|  quadra_ui (egui + egui_dock)       quadra_input (keymap, quad menus)        quadra_script (PyO3 + "quadra" script layer)     |
|        |  commands                      | actions                              | commands                                     |
|        v                                v                                      v                                              |
|  quadra_cmd  ---- command bus, undo/redo (persistent scene snapshots, Arc copy-on-write mesh buffers) ----                    |
|        |                                                                                                                      |
|        v                                                                                                                      |
|  quadra_scene (node tree, layers, selection sets)  ->  quadra_stack (dependency graph, lazy rayon eval, cache per mod)        |
|        |                                               |  uses quadra_geom (half-edge n-gon mesh, manifold booleans,          |
|        |                                               |  OpenSubdiv)  and quadra_modifiers                                   |
|        |  evaluated meshes (Arc, versioned)            v                                                                      |
|        +--------------------> quadra_viewport (wgpu: GPU-driven culling, instancing, outline, ID-buffer picking)              |
|        |                                                                                                                      |
|        +--------------------> quadra_render  = render bridge (Rust side): diff scene -> change set                            |
|        |                          |  cxx FFI                                                                                  |
|        |                          v                                                                                           |
|        |                    cycles_bridge (C++ shim, ours)  ->  Cycles standalone (Apache-2.0)                                |
|        |                          Session::reset on change, DisplayDriver writes into a wgpu texture                          |
|        +--------------------> quadra_io (USD native via openusd; ufbx, tobj, gltf; Alembic later)                             |
|  quadra_autosave (worker thread: serialise an immutable snapshot, never locks the scene)                                      |
|  quadra_plugin (versioned C ABI for native plugins; Wasm later for untrusted ones)                                            |
+-------------------------------------------------------------------------------------------------------------------------------+
     optional, separate process, never linked:  blender_helper  (headless Blender for .blend import only, over IPC)

Data path: the scene is the single source of truth. Each edit bumps a version on the changed node. The render bridge compares versions and sends only changed meshes, transforms, materials and lights to Cycles, then resets the session so the progressive render restarts. Cycles' Session and DisplayDriver classes make this possible (session.h, display_driver.h). Our material graph maps node by node onto Cycles shader nodes (scene.h). USD/Hydra stays a later option for render-farm export, not the live path.

The Blender helper is optional. Running Blender as a separate program and passing plain files is the safest reading of the GPL "aggregate" rule (GPL FAQ). This is a reading, not legal advice.

3. Hard targets and benchmark method

The Max baseline for each target is measured on the same PC with 3ds Max 2026, with no third-party plugins. The forum numbers in max2026.html section 10 are complaints, not baselines. Targets are ours and stay provisional until the M1 prototype is measured.

MetricTargetHow we measure
Cold start to usable viewportUnder 3 s, and at least 5x faster than Max on the same PCAfter a reboot, launch 10 times with a script. Time from process start until the first frame accepts input (the app logs a timestamp). Report the median.
Viewport FPS, 10M triangles60 FPS or better in shaded plus edges mode at 2560x1440, with 1,000 objects and 10% of them instancedA fixed scene (generated by a script, saved as USD and FBX for Max) and a fixed 30 s camera orbit. Log frame times and report the median and the 1% low.
Modifier stack re-evaluationUnder 50 ms when changing the top modifier of an 8-modifier stack on a 1M-polygon mesh. Under 200 ms when changing the bottom one.A scripted parameter change, repeated 100 times. Time from command to the evaluated mesh being ready. Same stack recreated in Max with its nearest modifiers.
File save and loadSave a 2 GB-in-memory scene in under 5 s without blocking the UI, and load it in under 8 sWall-clock time from command to done, 5 runs each, file on the same SSD. Autosave measures the longest UI frame while saving (must stay under 33 ms).
RAM useEmpty scene under 400 MB. 10M-triangle scene at most 60% of what Max uses.Peak working set from Windows performance counters after the scene has loaded and settled for 30 s.
UndoUnlimited steps. 1,000 edit-poly steps on a 1M-polygon mesh cost under 500 MB extra.A scripted edit session, then measure memory before and after.
Crash-free hours200 or more hours between crashes in soak tests. No work lost beyond 30 s.A nightly 8-hour randomised script (create, modify, undo, save, render) with crash counting, plus a kill-the-process test that checks the crash journal restores the scene.

4. Keymap and UI parity plan

  1. The default keymap is built from keymap.json (480 bindings). Action ids are our own snake_case names, and the visible labels are our own wording.
  2. The layout matches by default: menu bar and toolbar on top, a 2x2 viewport grid, the command panel on the right, the time slider and track bar at the bottom, then the status bar and prompt line. Every panel is a dock that can be moved, and layouts save as named workspaces.
  3. Everything can be rebound in the app, including mouse combos and quad menu contents. Conflicts show at once, and the user can export or import a keymap file.
  4. The settings page lists every option. Changes apply live and are saved straight away, with no restart.
  5. HiDPI and per-monitor scaling are tested from M1, because old UI scaling is a Max complaint (pain register).
  6. Gaps marked UNVERIFIED in section 2 of max2026.html get checked by watching public tutorials before M1 freezes the defaults.

8. Open questions

  1. UK price of 3ds Max: £1,640 a year excluding VAT, read from an Autodesk mirror page. Confirm it on the public UK store by hand.
  2. Which Cycles version to pin. From v4.0.0 to v5.2.0 Cycles had 426 commits in src/scene and 44 in src/session. That is churn, not proof of breaking changes, so plan one wrapper update per Blender release.
  3. The simulation layer (particles, cloth, physics) has no chosen crate yet.
  4. Whether egui's IME support is good enough for non-Latin users. Qt via cxx-qt is the fallback.
  5. Whether the "Quadra" name is safe to use in public (trade mark check).

9. One-page summary

9.1 Chosen route

A native Rust app with its own UI, scene, modifier stack and wgpu viewport. Final and interactive rendering uses standalone Cycles, linked through a small C++ wrapper that we write (blender-engine.html section 3). Blender itself is never linked. A headless Blender helper running as a separate process is optional, for .blend import only.

9.2 Licence

Cycles is Apache-2.0 (github.com/blender/cycles), so Quadra can use any licence, open or closed. Linking bpy or forking Blender would make the whole app GPL-3.0. That rules out those routes unless we choose GPL anyway. Blender add-ons will not run inside Quadra; that is the price of this route.

9.3 Top 10 Max pain points we fix

  1. Slow Slate material editor: the node graph is edited on its own thread and previews stream in.
  2. Licence cost: our own pricing, to be set. Max costs about £1,640 a year excluding VAT (UNVERIFIED, max2026.html section 10).
  3. Slow viewport on heavy scenes: GPU-driven culling, instancing and meshlets in wgpu.
  4. Windows only: Rust, wgpu and Cycles all build on Windows, Linux and macOS.
  5. Slow startup: plugins and Python load lazily, with the under 3 s target.
  6. Plugin version lock-in: a versioned C ABI, so plugins keep working across releases.
  7. Crashes and lost work: a crash journal plus autosave that never blocks the UI.
  8. Single-threaded modifiers: the dependency graph evaluates branches and per-element work in parallel with rayon.
  9. Undo limits: unlimited undo built on shared, copy-on-write data.
  10. Slow save and load, and old UI scaling: background, compressed USD writes; HiDPI tested from M1.

Ranking and evidence: max2026.html section 10.

9.4 Risks

  1. No Rust bindings for Cycles exist and its C++ API has no stability promise, so we own the wrapper and pin a version.
  2. wgpu at 10M to 50M triangles is unproven (UNVERIFIED). The M1 prototype comes first; ash/Vulkan is the fallback.
  3. Young crates: egui is still on 0.x, openusd is at v0.8, manifold-csg and opensubdiv-petite are small projects.
  4. Heavy C++ build: OIIO, OSL, Embree, OIDN, OpenVDB and OpenSubdiv. CI cost and Windows build time.
  5. Scope: the catalogue has 300 items. Full parity is years of work, so the MVP must stay to M1–M3.
  6. Legal: the "Quadra" name (past Apple use) and the clean-room record need a solicitor's check before a public release.
  7. Research quality: 60 of 300 catalogue items are still UNVERIFIED, and "verified" means the item has its own 2026 help page; parameter lists were not checked line by line.
  8. GPU vendor licences (CUDA, OptiX, HIP, oneAPI) limit what we can ship with the app. Review them before M3.
